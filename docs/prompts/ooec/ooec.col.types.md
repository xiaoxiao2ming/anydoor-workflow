# ooec.col.types —— 列类型注册表

> 右键列头弹出的那份菜单，**数据源就是本表**。
> 增删类型只改本文件 + `src/xlsx/outlineColType.ts`，不改任何 UI 代码。

---

## 1. 核心概念

**每一列 = 一个带类型的槽位。** 类型决定四件事：

1. 取值形态（文本 / 数值 / 引用）
2. 校验规则（填错了会不会被拦）
3. 是否参与联动（外部改参数时它会不会跟着变）
4. 是否参与导出（落到 xlsx 时写什么）

**同一列只能有一个类型。** 换类型走 `ooec.col.set`。

---

## 2. 类型清单

### 2.1 用户点名的 7 种（建议默认列序）

| 序 | 类型 | key | 取值形态 | 参与联动 | 参与导出 | 说明 |
|---|---|---|---|---|---|---|
| 1 | **名称列** | `name` | 文本 | ✗ | ✓ | 条目名称。**唯一在标题行也生效的类型** —— 承载章节标题文字 |
| 2 | **材料库对照列** | `matlib` | 引用（URN） | ✓ | ✓ | 指向材料库中的某条材料，改材料库 → 本列变 |
| 3 | **参数引用列** | `param` | 引用（URN） | ✓ | ✓ | 指向外部参数节点，取其计算值 |
| 4 | **单位列** | `unit` | 文本（受控词表） | ✗ | ✓ | `kg` / `m` / `m2` / `项` / `m3`… |
| 5 | **数量列** | `qty` | 数值 | ✓ | ✓ | 参与计算，默认小数位 3 |
| 6 | **系数列** | `coef` | 数值 | ✓ | ✓ | 参与计算，默认小数位 4 |
| 7 | **备注列** | `remark` | 文本 | ✗ | ✓ | 自由文本，不参与任何计算 |

### 2.2 扩展类型（非用户点名，按需启用）

| 类型 | key | 取值形态 | 参与联动 | 说明 |
|---|---|---|---|---|
| 单价列 | `price` | 数值 | ✓ | 常与 `qty` 相乘得金额 |
| 金额列 | `amount` | 公式或数值 | ✓ | 建议配公式 `=数量*单价` |
| 规格型号列 | `spec` | 文本 | ✗ | 如 `DN100 / PN16` |
| 品牌列 | `brand` | 文本 | ✗ | 材料品牌 |
| 损耗率列 | `loss` | 数值（%） | ✓ | 与 `coef` 相乘得实际量 |
| 分组列 | `group` | 文本 | ✗ | 用于 `GROUP BY`小计 |
| 自定义文本 | `text` | 文本 | ✗ | 兜底类型，随时可改 |

## 3. 类型定义结构

```ts
export type OutlineColTypeKey =
  | 'name' | 'matlib' | 'param' | 'unit' | 'qty' | 'coef' | 'remark'
  | 'price' | 'amount' | 'spec' | 'brand' | 'loss' | 'group' | 'text'

export type ColValueKind = 'text' | 'number' | 'reference'

export interface OutlineColTypeDef {
  key: OutlineColTypeKey
  label: string          // 右键菜单上显示的名字
  kind: ColValueKind     // 取值形态
  /** 是否在章节标题行上也有意义（目前仅 name=true） */
  validOnTitleRow: boolean
  /** 是否参与外部联动（外部变更时它会不会跟着变） */
  linked: boolean
  /** 数值精度；非数值型为 undefined */
  precision?: number
  /** 参考值的受控词表；自由文本型为 undefined */
  vocabulary?: readonly string[]
  /** 参考值的 URN scheme，如 ['lib'] / ['param','node'] */
  urnSchemes?: readonly string[]
  /** 一句话说明，鼠标悬停显示 */
  hint: string
}
```

## 4. 各类型的取值与校验细则

### 4.1 `name` 名称列

- 自由文本
- **标题行**（第一列非空）里，这一列的内容 = 章节标题文字
- 若一行有多个 `name` 列，**取最左边那个**作为章节标题来源
- 空名称的标题行仍可存在，但目录大纲上显示为「(未命名)」

### 4.2 `matlib` 材料库对照列

- 值必须是 **URN**，scheme = `lib`
  形如 `lib://brick/红砖MU10/0.24`
- 未对照时允许留空，**留空 ≠ 错误**（材料表允许「待定」）
- 填了非 URN 的自由文本 → 判为「未对照」，**不报错但标灰**
  （现状没有材料库节点，先按文本存，材料库落地后批量转 URN）

### 4.3 `param` 参数引用列

- 值必须是**纯 URN**，scheme = `param` 或 `node`
- ⚠ **口径来自 `docs/17-三项Excel能力结项.md`**：引用必须存纯 URN，
  存成 `数据排序 (2).数量` 这种可读原文 → `isPureUrn` 判否 → 当普通文本 → **联动永远不命中**
  （这是该批修掉的核心缺陷，别重犯）
- 必须从**计算后**的 `computeNode().fields` 取字段，
  不能从 schema 静态 `t.fields` 取（汇聚型节点自身 `t.fields` 是空的）

### 4.4 `unit` 单位列

- 受控词表：`kg` `t` `m` `m2` `m3` `个` `项` `套` `根` `m2` …
- 词表外的值**允许保存但标黄**，不强拦（设计院口径常常不统一，强拦会被骂）
- 单位不参与计算，纯粹是标注 —— 但**换算时要用它**（`m` → `mm` 不影响数值，`t` → `kg` 要 ×1000）

### 4.5 `qty` 数量列 / 4.6 `coef` 系数列

- 纯数值；非数值输入在commit 时归0 并 toast
- 精度：`qty` 3 位，`coef` 4 位
- **参与联动**：可被公式引用、可被触发规则写回

### 4.7 `remark` 备注列

- 完全自由文本
- 不参与联动、不参与计算、不参与校验
- 唯一约束：**不超长**（建议截断到 500 字符，Excel 单元格上限 32767）

## 5. 类型 → 落盘形态对照

| 类型 | xlsx 里存什么 | 打开时怎么读回|
|---|---|---|
| `name` | 文本 | 直接读 |
| `matlib` | URN 字符串 | 直接读（类型信息从节点配置读，不从单元格读） |
| `param` | 纯 URN 字符串 | 走 `readableToUrn` 的**逆过程** |
| `unit` | 文本 | 直接读 |
| `qty` `coef` `price` `amount` `loss` | 数值 | 直接读 |
| `remark` `spec` `brand` `text` | 文本 | 直接读 |

> ★ **列类型本身不落在 xlsx 里**，存在节点配置（`NodeConfig.chapterColTypes`）。
> 理由：xlsx 是给外人看的交换格式，不该塞本系统的私有元数据；
> 类型是「这个节点怎么解释这些列」的语义，属于节点而非文件。
> 代价：文件换了节点打开，类型就丢了 → 靠**列头文字**做兜底匹配（见 `ooec.col.set.md`）。

## 6. 类型与章节层的关系（写入边界）

章节编排是**结构调整**，不是数据编辑。写回xlsx 时的权限边界：

| 列 | 章节层能写吗 | 理由 |
|---|---|---|
| 第一列（标记） | ✅ 必写 | 唯一真相 |
| 第二列（编号） | ✅ 必写 | 派生值，重算后写静态值 |
| `name` 列 | ✅ 可写 | 章节标题的载体，属于结构 |
| 其余所有类型列 | ❌ **一律不碰** | 越权写会吞掉用户的业务数据 |

`writeOutline()` 当前写 A/B/C 三列 —— 对应本表即「A/B + 第一个 `name` 列」。
其余列保持原样，**这不是bug，是权限边界**。
