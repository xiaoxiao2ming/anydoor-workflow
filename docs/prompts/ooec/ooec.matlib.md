# ooec.matlib —— 材料库对照列

> 状态：规格已定，未实现
> 注意：当前**没有材料库节点**。本命令先按「文本对照」落地，材料库就绪后批量转 URN。

---

## 1. 用途

把材料表里的每一行与材料库中的条目建立映射，实现「改材料库 → 整表跟着变」。

---

## 2. 提示词

```
把 ooec 材料第 {工作表} 表的「{材料库列名}」列与材料库对照：

对照源：{材料库文件路径 或 材料库节点}
匹配键：{列名，如「材料名称 + 规格」}
匹配方式：{精确 / 包含 / 模糊}

逐行匹配，回报：
  · 匹配上的行数
  · 未匹配上的行（列出行号 + 原值），这些行标记为「待对照」
  · 匹配歧义的行（有多个候选，列出行号 + 候选清单），**不自动选第一个**

不要改动其他列的数据。
```

---

## 3. 数据形态

### 3.1 目标形态（材料库就绪后）

URN，scheme = `lib`：

```
lib://brick/红砖MU10/0.24
lib://pipe/DN100-PN16/钢
```

三段分别是：品类 / 规格 / 版本号。版本号让材料改版时能定位到具体条目。

### 3.2 过渡形态（**当前状态**）

没有材料库节点，先存**文本对照**：

| 状态 | 显示 | 含义 |
|---|---|---|
| 已对照 | 正常色 | 有 URN，能联动 |
| 待对照 | 灰色 | 空值 —— 允许，「待定」是正常业务状态 |
| 未识别文本 | 灰色 + 提示 | 填了非 URN 的文字，视为未对照，**不报错** |

> 为什么不强拦：材料表编制过程中大量条目是「先填名称、后对库」，
> 强制要求 URN 会让整个流程卡死。

---

## 4. 联动语义

材料库端条目变更时：

| 变更 | 本表反应 |
|---|---|
| 名称改了 | 跟随更新（若开了名称跟随） |
| 单价变了 | **不自动改本表** —— 价格由 `qty.link` 显式驱动 |
| 条目下架 | 标记「失效」，不删行（历史表要留痕） |
| 条目升版 | URN 里版本号变化 → 触发联动规则走一次 |

⚠ 联动**不走实时**，走 `ooec.link` 的规则触发（依据 `docs/15-联动触发规则-结项.md`）：
外部参数改了 → 匹配规则 → 命中才写值 + 重算 + 落盘；没命中 = 完全不动。

---

## 5. 输入输出

| 项 | 内容 |
|---|---|
| 输入 | 对照源、匹配键、匹配方式 |
| 输出 | `matlib` 列的 URN 或文本、匹配报告 |
| 副作用 | 无 —— 不改其他列、不落盘（除非后续 `ooec.link` 规则命中） |

---

## 6. 边界与坑

| 坑 | 处理 |
|---|---|
| 一个条目匹配到多个候选 | **列歧义清单，不自动选第一个** —— 选错材料是事故 |
| 材料库文件本身读不到 | 明确报错，不静默跳过 |
| 部分行匹配成功 | 正常，逐行回报成功/失败数，不整批回滚 |
| 材料库里有但表里没有 | **不主动加行** —— 材料表行序有业务含义（分部分项），AI 不得擅自增行 |
| 改这一列会不会影响章节结构 | 不会 —— 章节层只写第一/二列 + `name` 列，`matlib` 列不在写入范围内 |
