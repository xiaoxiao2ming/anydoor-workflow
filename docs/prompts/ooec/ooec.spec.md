## 1. 节点定位

**一句话**：Excel 全量功能 + 章节编排层 + 造价材料列体系。

它不是「一个新表格控件」，而是**现有 Excel 节点的外挂层**：

```
┌─ WorkbookEditor（现有，4266 行，本节点一行不改）─────────┐
│   公式求值 / 重算 / undo / 域绑定 / 引用对账 / 补丁保存    │
└──────────────────────────────────────────────────────────┘
                ▲
                │唯一接缝：outline 插槽（可选 props）
┌─ ooec 外挂层 ──────────────────────────────────────────┐
│   章节编排（第一列分级 / 第二列编号 / 目录大纲）           │
│   列类型系统（名称 / 材料库 / 参数引用 / 单位 / 数量 …）   │
└──────────────────────────────────────────────────────────┘
```

**这条边界是硬约束**：`WorkbookEditor` 里凡是ooec 专属的逻辑，一律写在
`src/xlsx/outline*.ts` 与 `ChapterDialog.tsx` 里。
判定标准——**若这段代码在普通 xlsx 节点里永远不会被执行，它就不该在 WorkbookEditor 里。**
（`outline` 插槽不传时，内核行为与改动前逐字节一致，这条已有 `git diff --stat = +74/-0` 实证。）

### 1.1 业务定位（为什么要这个节点）

来自 `docs/需求文档_C端Office编辑器.md` §2.2 流程模型：

```
项目立项 → 方案 → 初步设计 → 施工图 → 竣工 → 归档
   每阶段产出：说明书(Word) / 计算书(Excel) / 工程量表(Excel) / 材料表(Excel) / 设备清单 …
```

其中**材料表(Excel)** 就是 ooec 的原型：结构上分章节（分部分项 → 措施项目 → 其他项目），
每章下面是材料明细，每行有名称、单位、数量、系数、备注。

## 2. 列结构（★ 用户 2026-10-05 亲自定案，不可改）

### 2.1 三段式

| 段 | 列位 | 内容 | 性质 | 可编辑 |
|---|---|---|---|---|
| **第一列** | A | **字符标记**：用`#` 个数表达章节大小 | **唯一真相** | ✅（高级用户 / AI 写） |
| **第二列** | B | **自动编号**：关联联动章节，派生 | 派生值 | ❌ 只读 |
| **第三列起** | C+ | **自定义列**：右键列头选类型 | 业务数据 | ✅ |

### 2.2 第一列 —— 字符标记

| 输入 | 语义 | 内部level |
|---|---|---|
| （空） | 普通数据行，不参与编号 | 0 |
| `#` | 一级章节 | 1 |
| `##` | 二级章节 | 2 |
| `###` | 三级章节 | 3 |
| `####` | 四级章节 | 4 |
| `#####` | 五级章节（上限） | 5 |

**字符为主、 数字为兼容**（用户 2026-10-05 明确「用字符表达」）：

- 落盘写`#` 字符，**不是**数字 —— 导出到 Excel 别人一眼能看懂这是标题
- 读入时**同时接受** `1/2/3` 数字（历史文件、旧模板、宏业导出的表）
- 全角 `＃` 一并认（用户从别处拷来常见）
- 超长`######` 钳到 5 级

```ts
// 字符优先，数字兜底
export function parseLevel(raw: unknown): RowLevel {
  const s = String(raw ?? '').trim()
  if (s === '') return 0
  const m = s.match(/^[#＃]+/)              // ★ 先认字符
  if (m) return Math.min(m[0].length, MAX_LEVEL) as RowLevel
  const num = Number(s)                     // 兼容数字
  if (Number.isInteger(num) && num >= 0 && num <= MAX_LEVEL) return num as RowLevel
  return 0// 垃圾值 → 普通行，不抛
}
```

> ⚠ **与现有代码的差异**：当前 `outline.ts:156` 是**数字优先、字符兼容**，与本规格相反。需对调。
> 对调时注意：现有 32+81 条测试里有断言依赖数字优先，须同步改断言，**不是改测试迁就代码**。

### 2.3 第二列 —— 自动编号

- **派生值**，由 `renumber()` 全量重算，**永不手工维护、永不作为源数据**
- **关联联动**：任何结构变更（拖动 / 增删 / 升降级）后立即重排
- 打开 xlsx 时**以第一列为准重新解析并重算，第二列的历史值一律不认**
  ——否则用户手改过 B 列就会把编号带歪
- 落盘写**静态值**（导出到 Excel 能直接看见 `1.2.1`）
- 普通行（第一列为空）不编号，**且不打断上级计数器的延续**

关键实现（计数器栈，`counters.length = r.level` 这行不能省）：

```ts
constcounters: number[] = []
for (const r of rows) {
  if (r.level === 0) { r.no = ''; continue }   // 普通行不清计数器
  counters[r.level - 1] = (counters[r.level - 1] ?? 0) + 1
  counters.length = r.level                   // ★ 回到浅层级时作废深层计数
  r.no = counters.join('.')                    // 1 → 1.2 → 1.2.1
}
```

### 2.4 第三列起 —— 自定义列

**每一列都是一个带类型的槽位**。类型决定：取值形态、校验规则、是否参与联动、是否参与导出。

右键列头 → 弹出类型菜单。完整类型注册表见 [ooec.col.types.md](./ooec.col.types.md)。

速查（用户点名的 7 种，顺序即建议的默认列序）：

| 序| 类型 | key | 一句话 |
|---|---|---|---|
| 1 | 名称列 | `name` | 条目名称（章节标题行用它） |
| 2 | 材料库对照列 | `matlib` | 对应材料库条目的引用 |
| 3 | 参数引用列 | `param` | 引用外部参数节点的值 |
| 4 | 单位列 | `unit` | 计量单位（kg / m / m² / 项…） |
| 5 | 数量列 | `qty` | 数量（数值，参与计算） |
| 6 | 系数列 | `coef` | 系数（数值，参与计算） |
| 7 | 备注列 | `remark` | 自由文本，不参与计算 |

**关键约束**：
- 同一列**只能一个类型**，换类型走 `ooec.col.set`
- `name` 列是**唯一一个在标题行也生效**的类型（承载章节标题文字）
- 章节层**只写 A/B 两列 + name 列**，其余类型列一律不碰（越权写会吞用户数据）

## 3. 唯一真相与铁律

沿用 `docs/标题分级与目录大纲实现方案.md` §0，ooec 一字不改：

```
                 rows[]（唯一真相：level 字段）
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
   第一列字符标记    第二列编号      目录大纲树
     (# / ##)        (1.2.1)        (章节编排窗体)
        │              │              │
        └────── renumber(rows) ───────┘
              任何变更后全量重算一次
```

| # | 铁律 | 违反后果 |
|---|---|---|
| 1 | 编号是派生数据，永不手工维护 | 编号与层级对不上 |
| 2 | 树与表格是同一份 `rows` 的两个渲染，严禁两份状态互相同步 | 拖动后两边不一致，bug 之源 |
| 3 | 拖动 = 剪贴操作（摘出子树整段再插入） | 子树不跟走 |
| 4 | 全量重算几千行是毫秒级，**不做增量** | 增量必出漏 |
| 5 | 跳级一律钳制 + toast，**不静默** | 用户不知道为什么 `###` 变成了 `##` |
| 6 | 折叠状态存在**行**上（跟着行走），不存全局集合 | 拖动后折叠错乱 |
| 7 | ooec 专属逻辑不进 `WorkbookEditor` | oo 系列升级时冲突面爆炸 |
