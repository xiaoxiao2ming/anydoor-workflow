# ooec.param —— 参数引用列

> 状态：规格已定，未实现
> 口径依据：`docs/17-三项Excel能力结项.md`（引用必须存纯 URN）

---

## 1. 用途

让材料表的某列引用**外部参数节点**的值。上游参数改了，本表按规则跟着变。

---

## 2. 提示词

```
在 ooec 材料第 {工作表} 表的「{列名}」列写入对{上游节点名} 的引用：

引用字段：{字段名，如「数量」}
范围：{全部数据行/ 仅第 X~Y 行/ 匹配「{条件}」的行}

写入形式：纯 URN（如node://param_1786#value），
不要写成可读文字（如「参数节点 (2).数量」）—— 那样联动永远不命中。

回报：写入行数、跳过的行及原因。
```

---

## 3. ★ 铁律：必须存纯 URN

这是 `docs/17` 批**最核心的缺陷**，务必遵守：

| 写法 | 落盘结果 | 联动 |
|---|---|---|
| `node://param_1786#value` ✅ | 纯 URN，走 `isPureUrn` 分支 | **命中** |
| `参数节点 (2).数量` ❌ | 存成普通文本 | **永不命中** |

原缺陷现象：面板里能看见字段、点一下也确实插进了公式栏，看起来一切正常，
但提交后存的是可读原文 → `isPureUrn` 判否 → 当普通公式求值 → 联动规则永远不命中。
**症状极其隐蔽，插得进、存不进。**

配套要求（同一批修的）：

- 字段必须取**计算后**的 `computeNode().fields`
- **不能**取 schema 静态 `t.fields` —— 汇聚型节点（`sort`/`map`/`output`/`docx`/`xlsx`/`chapter`）自身 `t.fields` 是空的，字段全部继承自上游 `mergeComputed`

---

## 4. 数据形态

| 项| 值 |
|---|---|
| 落盘 | 纯 URN 字符串 |
| 读回 | 走 `readableToUrn` 的逆过程 |
| 显示 | 可读文字（`param://gas_pressure` → 「燃气压力」） |
| 引用失效 | 显示 `⚠引用已断开`，**不清空原值**（历史表要留痕） |

---

## 5. 联动语义

参数节点的值变化时：

| 步骤 | 行为 |
|---|---|
| 1 | 参数变化只产生**变更集**，不自动写文件（不实时） |
| 2 | 匹配 `ooec.link` 的规则 |
| 3 | 命中才写值 + 重算 + 落盘（去抖 800ms） |
| 4 | **没命中 = 完全不动**，一次 IO 都不发生 |

依据 `docs/15` 用户定案原文：

> 「我不需要实时动态的。我需要更新的时候更新」

---

## 6. 输入输出

| 项 | 内容 |
|---|---|
| 输入 | 上游节点、字段名、作用范围 |
| 输出 | `param` 列的纯 URN |
| 副作用 | 无 —— 写值由 `ooec.link` 的规则触发执行 |

---

## 7. 边界与坑

| 坑 | 处理 |
|---|---|
| 上游节点是汇聚型 | 走 `computeNode().fields`，不读 `t.fields` |
| 引用某个字段不存在 | 明确报错并列出该节点实际可引用的字段 |
| 引用链过深（param 引用 param） | 允许，但按 DAG 拓扑序写值，不递归触发 |
| 引用行被删了 | 章节层不管这列（`param` 列不在章节写入范围），由联动层对账 |
| 参数类型是字符串而列类型是 `qty` | 提示类型不符，**不自动强转** |
